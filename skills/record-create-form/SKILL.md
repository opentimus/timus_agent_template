# 通用记录建档（任意表，一步到位）

按语义包登记的表新建记录。**本技能不绑定任何具体实体**：表名、字段名、固定值、采集顺序全部来自语义包的运行时判定，不在本文件硬编码。

采集、写入确认两步法、逐条写入与部分失败处理一律遵循 `timus-app-schema` 的「录入与维护技能的通用规范」与 `references/write-contract.md`；本文件只写「怎么把一张表建成可用流程」。

## 触发条件

用户表达「建 / 新增 / 录入 / 创建 / 提交 / 登记」+ 任一表名（或明确的业务对象）时使用。可建单条或多条（同一组关联值）；只新建，不改既有；查询 / 修改 / 删除走 `record-maintenance`。本技能不查重、不覆盖已有记录。

## 第一步：锁定目标表

按 `timus-app-schema/references/intent-routing.md` 的「表定位规则」匹配语义包 `tables`：

- 完全同名或唯一子串命中 → 直接锁定，不追问。
- 命中多张表 → 弹窗选表。
- 一张都没命中 → 列出可用表名请用户指定，不新造表名、不跨表猜。
- 语义包仍是模板占位符 → 停止，先请用户提供应用编码与字段清单。

## 第二步：从语义包推导字段清单

对锁定表读取 `fields.<表>`，按 `type_policy` 分成四组——**这是唯一的分组依据，不要凭经验加字段**：

| 组 | 判定 | 处理 |
| --- | --- | --- |
| 不写组 | `AutoNumber` / `CreatedTime` / `Lookup` / `User` / `Formula` | 不进 `fields`，不进正文清单（除非用户要看） |
| 固定组 | 本技能声明的固定值（如状态初值、类型枚举） | 用预置值，不问用户，正文清单标注「固定」 |
| 关联组 | 类型 `Text` 且名字形如 `S.<实体>ID` | 先 `apaas_page_records` 查候选 → 弹窗；或由上一跳继承 |
| 待采集组 | 其余 `Text` / `Number` / `SingleSelect` / `DateTime` | 按「通用规范」的信息类别分别处理 |

必填判定：正文清单里凡「用户原话未给 + 语义包无可推导默认值」的字段，采集时逐项确认；缺失即剔除该条并说明「第 N 条缺 XX 已跳过」，不臆造、不写空占位。

## 第三步：采集顺序（有关联依赖时）

关联字段之间若有层级依赖（如「先选客户 → 再填项目 → 最后选交付单元」），**顺序由用户语义与候选间引用关系决定**，规则：

1. 被引用的父级排在被引用者之前（有 `S.<实体>ID` 指向它）。
2. 同一层级内按语义包 `fields` 的声明顺序。
3. 自由文本字段跟随其最近的关联字段同轮采集，不单独开一轮。

**无依赖的多条录入**：同批共用同一组关联值，逐条只差自由文本字段。
**有依赖的多条录入**：若一批要分属不同父级，提示用户分批，不静默拆批。

## 第四步：数值与日期

- `Number` 字段：`point_util.py normalize <值>` 得到 `text`（两位小数）与 `value`（写入值）。多条且有总量语义时用 `point_util.py split --total T --weight ...`，Σ 必须等于 T，逐条 ≥ 0.01。
- `DateTime` 字段：`date_util.py options` 出候选 → `batch` / `single` 出 `*_datetime`。禁止手拼时间格式、禁止心算星期。
- 单号类 `Text` 字段（流水号 / 订单号，用户未提供时）：`point_util.py next-pair`（一对）或 `next-batch`（多条）。

## 第五步：正文清单 + 精简确认框

按通用规范的两步法执行：摘要行（目标表 + 共用关联值 + 条数）+ 明细表（序号 + 各采集字段，固定值标注「固定」，敏感字段脱敏）+ `即将写入「<表名>」表，共 N 条，确认提交？`。

## 第六步：写入与回报

- 逐条构造 `apaas_add_record`（连接器无批量端点）；无依赖时同轮并行发起，有依赖时按依赖顺序串行。
- 全部成功：回报「主标识 → 记录 ID」清单 + 成功条数；`traceId` 为有效值时一并回报。
- 部分失败：按 `write-contract.md` 的「部分失败」处理，不重试、不静默补写。

## 禁止事项

- 不为「确认字段结构」多查一次表（字段来自语义包，已知）。
- 不凭记忆填写任何关联 ID；不手写表名、不跨表猜字段。
- 不把字段明细堆进弹窗；不以任何理由跳过正文清单 + 弹窗。
- 不写只读字段；不改既有记录；不绕过连接器直连 REST。
- 不在语义包未填充时进入写入流程。

## 示例（通用骨架，不绑业务）

用户：「新建一条 <表>，<名称> 是 XXX，<关联对象> 选 A，数量 6.567」
→ 锁定表 → 语义包推导字段 → 关联字段查候选并弹窗（首句已给则精确匹配）→ `normalize 6.567` → `7.00`… （按实际结果）→ 正文清单 + 精简确认框 → 写入 → 回报记录 ID。

用户：「批量建 3 条 <表>，都是同一个 <关联对象>」
→ 一次解析 3 条自由文本 → 关联值共用 → 缺项按条剔除并在清单下说明 → 一步到位确认写入。
