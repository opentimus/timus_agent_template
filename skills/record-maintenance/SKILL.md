# 通用数据维护（查 / 改 / 删）

对语义包登记的表做查询、修改、删除。新建记录不属本技能（走 `record-create-form`）。

参数语义、响应结构、错误处理、安全边界见 `skills/timus-app-schema/references/write-contract.md`；采集规范见 `timus-app-schema/SKILL.md`。
**本技能不绑定任何具体实体**：表名、字段名、关键字段全部来自语义包与运行时判定。

## 触发条件

用户表达「查 / 搜 / 列出 / 详情」「改 / 更新 / 修正 / 改状态」「删 / 删除 / 移除」时使用。覆盖语义包登记的全部表。**不新建、不批量、不改表结构。**

## 动作硬映射（命中即动作，不向用户确认动作类型）

| 用户关键词 | 动作 | 连接器工具 | 破坏性 |
| --- | --- | --- | --- |
| 查、查记录、查数据、搜、列出、有哪些、详情、看一下 | 查询 | `apaas_page_records`（列表）/ `apaas_get_record`（详情） | 否 |
| 改、修改、更新、修正、改成、设置为、改状态 | 修改 | `apaas_edit_record` | 否（但必经最终确认框） |
| 删、删除、移除、删掉、清掉 | 删除 | `apaas_delete_record` | 高（需二次确认） |

- 意图含糊（如「处理一下这条记录」）先弹一次 `AskUserQuestion` 选动作，不猜测。
- 数值 / 日期类字段的修改同样走 `point_util` / `date_util`，不口算、不手拼格式。

## 表与字段定位

- 表名按 `intent-routing.md` 的「表定位规则」匹配语义包 `tables`；命中多张弹窗选表，零命中列可用表。
- 字段名逐字用语义包 `fields` 下的系统字段名，禁止历史别名或界面标题。
- **可写性以 `type_policy` 为唯一权威源**：`AutoNumber` / `CreatedTime` / `Lookup` / `User` / `Formula` 只读；未知字段直接拒绝并请用户给出准确字段名。

## 「关键字段」怎么定（删除与修改的复述依据）

不硬编码业务字段名，按下列顺序取第一个可用者作为记录的可读标识：

1. 语义包中该表第一个 `Text` 类型、名字含「名称 / 标题 / 单号 / 编号」的字段；
2. 否则取第一个 `Text` 字段；
3. 都没有则用 `record_id` 本身。

复述时「关键字段值 + record_id」一起给出，避免同名记录误删。

## 一、查询（无破坏性，直接查）

- **列表 / 搜索 / 筛选** → `apaas_page_records`：`app_name` + `table_name` + `page_size`（≤50），条件用 `query_fields`（operator 默认 `eq`），多条件用 `conjunction`，只要部分字段用 `return_fields`，排序用 `sort_fields`。飞书数据源续页传 `page_token`（不与 `page_num` 混用）。
- **按记录 ID 取详情** → `apaas_get_record`：`app_name` + `table_name` + `record_id`。

查询直接调用，无需确认框；结果回报匹配条数与关键字段，无匹配如实说明，不编造。统计 / 对账在查询结果上完成，不另建表。

## 二、修改（先查询确认目标，再确认后写）

1. **定位目标记录**：有 `record_id` 直接用；无 ID 先 `apaas_page_records` 查询，**查出必须唯一**（0 条回报未找到；多条请用户补充条件或给 `record_id`，不擅自挑一条）。可用 `apaas_get_record` 取回当前值让用户确认改哪几个字段。
2. **采集新值**：逐项对话采集；字段名与类型按语义包校验，只读字段直接拒绝。**一次只改一条记录。**
3. **构造参数**：`apaas_edit_record`，`fields` 只放要改的字段；`record_id` 与 `query_fields` 二选一（都给时以 `record_id` 为准）。
4. **最终确认框（必经）**：复述「表名 / 记录 ID / 关键字段值 / 每个字段的旧值 → 新值」；选项 `确认提交`（首位、「（推荐）」）/ `取消 / 返回修改`。即使用户说「直接改 / 不用确认」也必须弹框。
5. 调用后回报记录 ID 与 `traceId`（有效时）。

## 三、删除（破坏性，二次确认，不可撤销）

1. **定位目标记录**：同修改——有 `record_id` 直接用，无则先查询且**必须唯一**；可先 `apaas_get_record` 取回完整字段确认是目标记录。
2. **二次确认（必经，不可跳过）**：弹 `AskUserQuestion`，写明「**删除不可撤销**」，复述「表名 / 记录 ID / 关键字段值」；选项 `确认删除`（首位、「（推荐，不可撤销）」）/ `取消`。
3. **构造参数**：`apaas_delete_record`，`record_id`（推荐）；无 ID 用 `query_fields` 唯一定位。
4. 调用后回报被删记录标识与 `traceId`（有效时）；删除后不自动重查（记录已不存在）。

即使用户首句说「直接删 / 不用确认」也绝不省略；不得用文字复述替代弹窗（除非宿主确实无弹窗能力，此时文字须含「不可撤销」并收到明确「确认删除」）。

## 降级与禁止

- 弹窗不可用 → 文字逐项复述：改须收到明确「确认」，删须收到明确「确认删除」；专家不中断。
- 不写只读字段；不凭记忆填 `record_id`，候选必须来自查询。
- 不批量修改 / 删除；一次只操作一条记录。
- 不删表、不改表结构、不新建记录；只操作语义包登记的表。
- 同一条改 / 删不重复提交（可能已成功）；查询可安全重试；删除失败不自动重试。

## 示例（通用骨架）

- 「查一下 <表> 里 <状态> 为 X 的记录」→ `apaas_page_records`（`query_fields` = `<状态字段> eq X`，`page_size=50`）→ 回报列表。
- 「把 <表> 里 XX 的 <字段> 改成 YY」→ 定位（唯一）→ 复述旧值 → 新值 → 最终确认框 → `apaas_edit_record` → 回报。
- 「删掉 <表> 里 XX 这条」→ 定位（唯一）→ 二次确认框（含「不可撤销」+ 关键字段值 + record_id）→ `apaas_delete_record` → 回报。
