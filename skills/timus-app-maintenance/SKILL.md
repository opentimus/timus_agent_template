# 基础数据维护（查 / 改 / 删）

对本地基础数据（`timus-team-data.yaml`）做查 / 改 / 删；表名与字段名取自表头元数据（`timus-team-schema.yaml`）。**不绑定具体实体**：表名、字段名、关键字段均由 schema 判定。

## 触发条件

「查 / 搜 / 列出 / 详情」「改 / 更新 / 修正 / 改状态」「删 / 删除 / 移除」。覆盖本地基础数据全部表；**不新建、不批量、不改表结构**。

## 动作硬映射（命中即动作）

| 用户关键词 | 动作 | 脚本参数 | 破坏性 |
| --- | --- | --- | --- |
| 查、查记录、查数据、搜、列出、有哪些、详情、看一下 | 查询 | `--table` + `--where` / `--fields` | 否 |
| 改、修改、更新、修正、改成、设置为、改状态 | 修改 | `--record` + `--set 字段=值` | 否（必经确认框） |
| 删、删除、移除、删掉、清掉 | 删除 | `--record` + `--delete` | 高 |

- 意图含糊（如「处理一下这条记录」）先弹 `AskUserQuestion` 选动作。
- 数值 / 日期字段修改同走 `point_util` / `date_util`，不口算、不手拼。

## 表与字段定位

- 表名按 `timus-app-schema/references/intent-routing.md`「表定位规则」匹配表头元数据 `tables`；多张弹窗选，零命中列可用表。
- 字段名逐字用系统字段名，禁历史别名 / 界面标题。
- 可写性以 `type_policy` 为准：只读类型拒写；未知字段直接拒绝。
- 记录 ID 由本地基础数据提供，禁凭记忆填写。

## 「关键字段」怎么定（复述依据）

不硬编码业务字段，取第一个可用者：

1. 该表首个 `Text` 且名含「名称 / 标题 / 单号 / 编号」的字段；
2. 否则首个 `Text` 字段；
3. 都没有用记录 ID。

复述时「关键字段值 + 记录 ID」并给，避免同名误改 / 误删。

## 一、查询（无破坏性）

```bash
python3 <skill-dir>/scripts/data_tool.py --list-tables
python3 <skill-dir>/scripts/data_tool.py --table <表名>
python3 <skill-dir>/scripts/data_tool.py --table <表名> --where "S.字段=值" --fields "S.字段A" "S.字段B"
```

`--where` 可重复（AND），`--fields` 可多值。直接执行；回报条数与关键字段，无匹配如实说明，不编造。统计 / 对账在结果上完成。

## 二、修改（先定位，确认后写）

1. **定位**：有记录 ID 直接用；无则查询且**必须唯一**（0 条报未找到；多条请补条件或给 ID，不擅自挑）。
2. **采集新值**：逐项对话；字段名 / 类型按表头元数据校验，只读字段拒绝。**一次只改一条。**
3. **确认**：复述「表名 / 记录 ID / 关键字段值 / 各字段旧值 → 新值」；选项 `确认提交`（首位、「（推荐）」）/ `取消 / 返回修改`。
4. **执行**：`--record <记录ID> --set "字段=值"`，只改已存在字段，不新增字段；回报旧值 → 新值。

## 三、删除（破坏性）

1. **定位**：同修改——有 ID 直接用，无则查询且**唯一**。
2. **执行**：`--record <记录ID> --delete`；回报被删标识，删后不自动重查。

## 降级与禁止

- 弹窗不可用 → 文字逐项复述：改须明确「确认」。
- 不写只读字段；不凭记忆填记录 ID，候选来自查询。
- 不批量改 / 删；一次只操作一条。
- 不删表、不改表结构、不新建；只操作登记的表。
- 同一条改 / 删不重复提交；查询可重试。

## 示例

- 「查客户里状态为 X 的记录」→ `--table 客户 --where "S.状态=X"` → 回报列表。
- 「把客户里 XX 的字段改成 YY」→ 定位唯一 → 复述旧值 → 新值 → 确认框 → `--set` → 回报。
- 「删掉客户里 XX 这条」→ 定位唯一 → `--delete` → 回报。
